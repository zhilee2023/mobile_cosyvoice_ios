## 证据与当前选择

输入证据：用户统一报告 `cosyvoice-test-report(1).json`，v0.7.1/build15。
独立Flow线程行由 `scripts/inspect_test_report.py` 解码实际Mel核对，要求
相同版本、模型文件戳、固定输入；文件戳不是内容哈希。下表为这批样本，
不是不同温度/系统负载下的普遍速度保证。

| 路线 | 预热耗时 | 判定 |
| --- | ---: | --- |
| Flow High 4线程、两步 | 1.810秒 | 当前基线 |
| Flow High 2线程、两步 | 2.219秒 | L2=2.734e-5；无明显内存收益，归档 |
| Flow High 3线程、两步 | 2.385秒 | L2=2.739e-5；无明显内存收益，归档 |
| HiFT Low 4/2/3线程 | 0.359/0.440/0.451秒 | 与前几轮一致，保留4线程 |
| Flow 整图BF16 | 首次一步即全NaN | 不能把失败时的小内存当成功收益，归档 |
| Flow 384/352/320 | 2.058/1.944/1.803秒 | 按32帧对齐已在生成使用，不再重复计收益 |

Flow线程峰值约1536–1543 MB；减少线程几乎不省权重/工作区。
HiFT core Low由用户试听选择，F0仍High；保留音质开关，不再保留精度探针。
LLM旧独立微基准可支持复用和每句清KV，不能代替全链验收。新版中LLM路线
因启动规划门槛而未运行的记录，不算新数值失败，也不需要重复同一微基准。

完整生成：Low基线7.68秒音频/15.030秒计算，计算RTF=1.957；首次入队5.465秒，
峰值1587 MB、最低余量1634 MB、2次断供共4.418秒。自适应Flow常驻8.40秒音频/
16.819秒计算，RTF=2.002，启动后释放Flow且三句均回退串行。两者speech token
数不同，不能严格声称慢了多少，但现有入口未证明常驻带来收益，应撤下。
最新另一轮RTF=1.782关闭了HiFT Low且音频变长，不是High比Low快的A/B证据。

## 下一步，只推进一个完整链路实验

**优先：仅保留一套LLM实例，每句reset KV、重新prefill，声学模型顺序运行。**

- 先PC同输入确定性采样核对独立/复用的speech token、EOS；再生成同token声学
  对照，检查PCM/Mel、RMS和试听。保留生产采样另测，不能拿随机时长作严格A/B。
- 真机先3句完整EOS→Conditioner→Flow High→HiFT Low。LLM存活期间Flow执行属于
  内存共驻，尽管二者不同时计算；不能直接套用“销毁LLM后等待2500 MB”的串行门槛。
  需要分阶段规划加载/resize/运行余量，保留20ms采样与最低800 MB底线；不足就
  关闭候选并安全回退，记录保护/重试代价，不无条件下调门槛。
- 每句清KV，不保留跨句历史；同一批只有一个LLM，不创建隐藏Flow会话池。
  结束、取消、NaN、EOS超限、写文件失败均回收；不靠删字/强制EOS冒充读完。
- 通过短句后再测30/60秒及分钟级长文、两次连续批次、取消和恢复。播放队列目标
  2秒/上限4秒、至多一句待播文件；不能用无限队列隐藏断供。
- 验收同时看计算RTF、墙钟RTF、首句入队（非扬声器实测）、断供次数/秒数、
  每段EOS与时长、内存峰值/最低余量、生命周期结束回收。所有初始化/等待/失败
  尝试计入，不只挑预热kernel时间。

收益上限需保守：7.68秒Low基线中，后两次LLM加载约0.773秒；只消掉这些，
简单反事实算式(15.030-0.773)/7.68≈1.856，而非直接到1.5，更不是已测速度。
如果后续还安全消掉两次Flow resize约1.884秒，算式才到约1.611。
共驻工作区、等待、热状态与采样差异可能吃掉收益。不能承诺RTF<1或绝不OOM。

## 后续优先级与退出条件

1. 仅LLM全链复用通过，才研究唯一320/352/384 Flow会话复用；按完整EOS长度
   选容量，不截断输出。同一时间最多一个Flow。以初始化、内存和稳定RTF共同选型。
2. 如果LLM＋Flow共驻不够，候选是**有限2句token预生成→释放LLM→声学阶段复用**。
   token占用小但首句等待会增加；明确记录首包代价，不能叫token级流式。不先实现
   权重预取、并行线程和多会话池来赌内存。
3. 短首句、后续3–4秒完整句：摊薄prompt/加载开销，但改变韵律，需重听与测断供。
4. 真token流式另立声学导出门槛。官方hop/lookahead/token_offset/finalize、HiFT
   缓存需和本包2步学生图匹配；当前离线前缀PC实验声学一致性没通过。不能简单把
   WAV切块或重复离线前缀就当成真流式。
5. BF16首个坏算子定位、敏感算子保高精度与W8是后续专项。整图BF16不重复；W8
   要匹配学生原始权重/导出链，不能拿文件重命名或无效FP16重转当已量化。

长尾耗时（曾有单步10秒）仍需CPU/wall时间、应用前后台、热状态与内存时序定位，
不凭一个墙钟间隔直接断定MNN死锁、内存不足或降频。
