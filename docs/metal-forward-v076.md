# v0.7.6 Metal Flow 前向测试

## 已有证据

v0.7.5两次独立256帧Metal Low/NoTune会话：主pipeline backend=1，20ms采样峰值2092/2062MB，最低可用1129/1159MB。未运行前向。此前Metal High仅resize最低可用约476MB，不继续重复High配置。

同份报告CPU三句分阶段链路：8.52秒音频，计算12.934秒/RTF1.518，首块入队7.952秒，最低可用1601MB，断供0次。GPU模块实验与这些整链数值分开记录。

## 操作

1. 安装v0.7.6/build20，冷启动，单独点“① GPU 256帧”。
2. 返回后重新冷启动，点“② GPU 384帧”。若第一项出现NaN或内存停止，先回传报告，无需继续第二项。
3. 分享同一个cosyvoice-test-report.json。新路线会保留每个步骤和失败时已经完成的记录。

## 实现与验收

- 固定25/70个真实speech token，加87个音色提示token；有效224/314帧，分别补零到256/384。相同Conditioner、mask、noise、spks和cond供两个后端使用。
- Metal Low、Memory Low、NoTune，主backend必须为Metal。后端逐算子回退仍可能存在。
- 初始余量至少2900MB。GPU resize后至少1100MB用于前向规划；所有阶段20ms采样及当前可用内存底线800MB。采样不能保证捕捉所有短暂分配，真机仍可能被系统终止；中断后统一报告恢复日志。
- 每会话三轮、每轮重置相同初始latent并运行两步；每步重新上传全部六个输入。分项input/run/read-sync，输出形状、类型、有限值和重复性检查。GPU异步执行的等待包含在read-sync中，不能把run单独当完整推理耗时。
- Metal会话先析构，再等待至少2500MB余量才创建CPU High四线程参考；GPU与CPU不同时驻留。若残留分配未回收，保留GPU实测并标记CPU参考未运行。
- 比较目标区域Mel的相对L2、相关性、增益；严格L2门槛保持1e-3。Low精度超出此门槛时标为需质量复核，不将有限值自动等同音质通过，也不将数值差异直接等同GPU不可用。
- 不运行LLM、HiFT或播放；首次和预热仅是Flow两步耗时。通过后才接真实文字与HiFT测整链、试听和长文本稳定性。
- 已有resize探针撤下运行按钮，结论保留在归档区。原有17个模型文件和正式CPU链路配置不变。
