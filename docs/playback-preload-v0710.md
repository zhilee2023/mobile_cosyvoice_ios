# v0.7.10 / build24：五句播放缓冲对照

用户要求本轮只测五句；移除默认30/60秒文本按钮，默认载入原预置文本前五句。历史长文生成与数据不删除，模型17个文件不变，ACE不改动。

## 选择的播放模式

- **首句即播（对照）**：原始行为。最多一条待播句段，生成供给较慢时可能逐句断供。
- **预加载三句再播（默认）**：相同CPU三句批量生成。前三句完整WAV准备后播放，继续生成后两句。短于三句时在生产完成后直接播放现有句段。若后续真正耗尽，界面明确显示补缓冲，至多等三句或生成结束，不把等待隐藏成成功。
- **全部生成后播放**：先完成合并WAV并关闭模型，再从文件以200ms块送入原播放器，不受后续推理供给影响。等待更久，不是即刻/实时生成；不保证系统音频中断或系统负载下绝不会停顿。

这是音频缓冲，不是已实现App启动LLM常驻，也不修复GPU数值问题或降低模型计算RTF。

## 内存与磁盘

只有原单推理队列运行模型；播放器并行读已完成文件。预加载使用本次独占的UUID临时目录，每条WAV先复制再允许下一轮native覆盖固定输出名。活跃feeder计入6个文件硬限，临时句段总大小≤8MiB，达到上限时暂停生产等待播放释放。此上限不含最终合并WAV。

内存播放队列仍目标2秒/硬限4秒，每次分配≤200ms PCM，不把五句/整篇一次性转成PCM数组。每个临时文件读完即删除；结束或取消先等待feeder返回，再删除本次创建的精确UUID目录；不得删除模型、历史成功WAV或用户文件。异常仍保留partial合并WAV，不标成整篇完成。进程崩溃后的临时文件由系统临时目录策略管理，不宣称跨崩溃磁盘总量硬限。

取消不强杀native推理；返回后释放模型。停止/播放异常时不再把gapCount和gapSeconds清零，新测试开始才重置。旧报告取消记录中的0次断供不可作无断供证据。

## 指标与验证

统一报告增加playbackMode、initialBufferAudioSeconds、rebufferCount、peakPlaybackDiskFiles/Bytes、elapsedIncludingPlaybackSeconds；firstQueuedSeconds仍表示首块入队，不是扬声器实测。计算RTF包括模型初始化/失败/清理；generationWall计入生产背压，elapsedIncludingPlayback包含预等待和实际播完时间。不得只报告缓冲后播放速度而宣称推理提速。

确定性调度例：五句各2.8秒、生产RTF1.8，前三句生成后开始，剩下两句需10.08秒生产，短于待播放的14秒，所以有机会覆盖缺口。实际句长/批量准备/降频可能不同，长文RTF>1时三句缓存仍可能耗尽，需要补缓冲或使用完整生成后播放。

云端Foundation测试：0/1/2/3/5文件起播、最后不足三句、完整模式结束条件、6文件与8MiB边界、负数/空数据拒绝、简化调度模型；拆句测试确认预置文本确实五句且不丢字。编译通过不等于iPhone听感通过。

操作：保持同一默认五句，先选预加载三句测一次；再冷启动选全部生成后播放测一次。需要对照时加测首句即播。只发统一cosyvoice-test-report.json，报告内保留温度、内存、实际gap及播放策略。

六句批量build23未显示整体速度优势，归档其UI按钮；实现与历史数据保留。
