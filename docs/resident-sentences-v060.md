# v0.6.0（build 12）：一批一句流，唯一 Flow 常驻

ACE 项目不动，模型17文件不变；覆盖安装即可，不需要重新导入模型。

## 改动与边界

- 新增独立入口“按句生成 · 常驻Flow384 · 新实验”。原逐句释放入口、2/4线程对照与单句生成保留。
- 新入口固定CPU 4线程，Flow CPU High / Memory Low / 384帧 / 两步，DSP优化；HiFT F0与core仍为High。不采用已发现明显波形差异的HiFT Low，不启用Flow Low或Metal。
- 一批只创建、resize一次Flow，所有句段复用同一会话，每步重传六个输入，重建补零区与mask。没有隐藏会话池。
- 每句新建LLM、重新prefill，使用当前句文字和音色提示，必须生成合法speech token并正常EOS。LLM销毁后才运行Conditioner/Flow/HiFT；不保留跨句KV、不并行计算两模型。仅Flow可与LLM或HiFT共驻。
- 384帧含174帧提示，剩210帧=105 speech token=4.2秒。因此新入口的每段容量小于旧串行入口160token/6.4秒；这是实现边界，不是模型理论最大时长。
- 按标点及18个UTF-16单元初拆句；超speech上限不截断、不补假EOS，而是二分重试（至多3层/128段）。2000 UTF-16输入上限不变，不保证所有2000单元输入都能在128段内完成。
- 第一段WAV生成后入播放队列，播放与下一段推理重叠；目标≤2秒、硬上限4秒队列，只保留两条交替短文件和流式写入的合并WAV。不是句内token级流式。
- Flow会话通过批次对象拥有，成功、失败和用户停止后的当前调用返回时显式close；兜底析构也释放。关闭前isRunning保持true，不允许同时启动另一模型任务。

## 内存保护

初始化前等待可用内存≥2900 MB连续两次（100ms间隔、至多5秒），不是一瞬未达标立即失败。Flow初始化后、每句LLM加载前以及LLM销毁后需≥1500 MB连续两次；HiFT前仍需1000 MB。保留原串行入口2800/2500 MB门槛，仅常驻入口使用共驻专用检查。

初始化、每句推理和close均约20ms采样；每句LLM前向前/后、Flow各步前/后、HiFT完成后核查当前及本句采样最低值≥800 MB。单次MNN调用无法从外部强行中止，采样检查可能在调用返回后才发现压力；不能保证不会被系统终止，也不是OS峰值上界。初始化失败或门槛不通过不自动降精度、不自动降低门槛。

已知证据：v0.5.1唯一Flow384＋LLM prefill＋2 decode短KV探针峰值2308 MB、最低可用913 MB；共驻及释放后Flow相对独立基线L2=0。它没有完整EOS、没有HiFT，不证明本版完整句段或分钟级常驻安全。

## 真机测试顺序

1. Sideloadly覆盖安装0.6.0（build12），不卸载旧App；确认模型17/17。
2. 冷启动，填入三句测试文字，点“按句生成 · 常驻Flow384 · 新实验”。不要同时跑其他探针；确认每句真实发声、无漏读/重复/爆音。
3. 分享“句级汇总日志”“各句模型诊断”“常驻Flow生命周期”和完整WAV。初始化日志应只有一次resize，所有句段日志应显示复用、LLM EOS、两步有限、HiFT High。
4. 在相似设备温度/前台条件下冷启动跑原逐句释放入口（优化开、4线程）对照。随机采样会改变speech长度；不能仅用两次不同音长RTF断言精确加速比例。
5. 三句成功后再测10句，关注逐句峰值/最低可用有无持续增长、播放队列断供和句间自然度。再测中途停止、重新开始、超长句拆分重试与失败后可重启；暂停/来电等音频中断也应停止或安全恢复，不允许队列无限堆积。

RTF口径：计算RTF包含一次Flow初始化和全部成功/失败重试的native调用时间；另记不含初始化的稳态计算RTF。生成墙钟包含回收和队列等待以及关闭Flow，不包含最后扬声器排空时间；首块入队不是扬声器首声。队列断供次数是应用观测。保护门槛等待、重试与冷启动可能抵消省下的resize；不预先承诺RTF低于1。

文件`last-resident-lifecycle.log`记录初始化/关闭，两个阶段的时间都从各自调用开始计；`last-sentence-stream.log`是整批统一时间轴。完整句段诊断逐句追加，进程退出后重开仍可分享已写入文件。旧成功WAV不代表本次成功；未完成音频保留partial，不冒充完整输出。
